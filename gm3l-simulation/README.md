# GM³L simulations

Simulation code for the Gaussian mixture model with must-links (GM³L).
It compares SMLE, the complete-data ORACLE estimator, and FINAL for parameter
estimation, and compares GMM, SMLE, and FINAL for clustering.
All observations and must-links are generated by the code. No real data,
precomputed estimates, or external experiment directories are required.

## Setup

Use Python 3.10–3.12. Python 3.10 and the versions in `requirements.txt` match
the original numerical environment.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

On Windows, activate the environment with `.venv\Scripts\activate` instead.
Run the following commands from this directory.

## Quick check

```bash
python -m unittest discover -s tests -v
python scripts/run_simulation.py --config configs/smoke.json --output results/smoke
python scripts/plot_results.py --results results/smoke --output figures/smoke
```

The smoke configuration uses two replications at n = 200 and 400. It tests
the full workflow, not the asymptotic conclusions of the paper.

## Paper experiment

```bash
python scripts/run_simulation.py --config configs/paper.json --output results/paper --workers 1
python scripts/plot_results.py --results results/paper --output figures/paper
```

The paper configuration uses K = 3, p = 5, 500 replications, and
n = 3200, 6400, 12800, and 25600. `gm3l/data.py` contains the fixed mixing
weights, means, covariance matrices, and must-link probabilities.
The off-diagonal must-link probability is 0.15 and the diagonal probability
is 0.70. The simulation parameters are fixed in `gm3l/data.py`.

Each replication generates a dataset of size 25600 and uses its prefixes for
the four sample sizes. The seed is
`SeedSequence([2026101101, 3, 5, replication])`, with replication numbered from
1 to 500. This regenerates the complete sequence directly; no earlier saved
replications are needed. Generating each sample size separately would give
different data and would not reproduce this experiment.

NumPy/SciPy is the default backend. On macOS, the original Accelerate backend
can be selected with `--backend accelerate`; use a different output directory
when changing backend. Numerical libraries and eigensolvers can produce small
floating-point differences across platforms. Fixed seeds do not imply
bit-for-bit identical fitted estimates on every platform.

The largest experiment uses a dense adjacency matrix. A single float64
25600-by-25600 matrix occupies about 5.24 GB, and fitting needs additional
working memory. Start with one worker; concurrent workers each require their
own dataset and fitting memory. Full reproduction is substantially larger
than the smoke test.

## Estimators and evaluation

- SMLE uses adjacency-based spectral initialization, row normalization, and
  K-means with 10 starts. The initial covariance is pooled and the initial
  must-link probabilities are 0.70/0.30. Stopping uses a parameter-step
  tolerance of 1e-6 and a checked fixed-point residual, with at most 20000
  iterations. No covariance ridge or probability clipping is added.
- ORACLE uses the generated class labels. SMLE and FINAL do not use those
  labels during estimation. A fitted SMLE label permutation is found only for
  evaluation and is shared by SMLE and FINAL.
- FINAL is constructed from the soft SMLE posterior probabilities. Its
  clustering probabilities are then recomputed at the FINAL parameters.
- GMM uses X alone, three full-covariance components, and ten deterministic
  starts. The converged fit with the largest observed-data likelihood is
  selected. Class labels are used only afterwards for alignment and scoring.
- Parameter MSE averages squared errors over all entries of each parameter
  block, including the full covariance and must-link matrices. Posterior MSE
  averages over all nK probabilities. Its natural logarithm is computed from
  logits with log-sum-exp, without an epsilon or a floor for small errors.

## Outputs and restarting

`all_results.csv` contains one row per replication, sample size, and method.
Per-fit JSON files retain diagnostics and failure statuses. `generation/`
records seeds and adjacency checksums; `configuration.json`, `environment.json`,
and `source_hashes.json` record the run specification. `status.json` and
`completion.json` distinguish a complete run from one with missing or failed
fits. The `--save-estimates` option additionally saves parameter arrays.
Simulated observations and dense adjacency matrices are not saved by default.

Repeating the same command resumes at missing fit records. Completed failures
are retained rather than silently replaced. Changes to the configuration,
source, backend, or numerical environment require a new output directory.
Run only one driver per output directory at a time. `--replications 1` is
available for a trial with the same sample-size grid; it is not a full
500-replication reproduction.

The plotting script produces the three simulation figures: Gaussian mixture
parameter errors, must-link probability errors, and clustering posterior
errors. It checks completeness and fit statuses before plotting. It preserves
the paper's panel structure; PDF metadata and rendering may differ between
Matplotlib versions.

## Layout

```text
gm3l/                    Model, estimators, initialization, and evaluation
configs/paper.json       Full paper experiment
configs/smoke.json       Small end-to-end check
scripts/run_simulation.py
scripts/plot_results.py
tests/                   Numerical and workflow checks
requirements.txt         Pinned dependencies
```

Generated results and figures are excluded by `.gitignore`.
